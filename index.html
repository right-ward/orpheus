Make a destructive change less destructive.

Orpheus is an Android-first preservation project for the data and application state you may want to keep before a bootloader unlock, factory reset, or another operation that wipes user data. It focuses on collecting what Android legitimately makes accessible, checking the resulting archive, and making gaps visible instead of promising a perfect device clone.

Orpheus does not bypass a mandatory wipe or perform the destructive operation. The current app builds and verifies preservation archives; restoration is still future work.

What it can preserve today

User-selected files

Select folders through Android's document picker. Orpheus enumerates the selected trees and streams file contents into a compressed .orpheus archive, rather than loading whole files into memory. It records a logical manifest and per-file SHA-256 checksums, then reopens the finished archive and verifies its payloads. The app also estimates the selected content size and records interrupted or incomplete backup sessions.

Installed application inventory

Record the packages Android makes visible, including version and signing-certificate metadata, requested and granted runtime permissions where available, and information relevant to a later restore plan. APK preservation is a separate option: Orpheus can save obtainable base APKs and split APKs, verify them, and report items it could not read instead of silently omitting them.

Optional Shizuku-assisted reads

When Shizuku or Sui is available and authorized, Orpheus performs a bounded, read-only diagnostics probe. After that probe succeeds, it can use a narrowly scoped fallback to read certain PackageManager-reported APK files under /data/app/ when normal app access fails. It can also collect a small, opt-in allow-list of system settings; that snapshot is partial and is not currently restored.

Designed around explicit limits

Android access depends on the device, OS version, package, and available privilege. Shizuku's shell/ADB access is not the same as root, and a successful probe does not mean all protected data is readable. Orpheus reports inaccessible or failed artifacts rather than treating every collection as complete.

The project is currently in Phase 4 — Shizuku integration. Personal-data collectors, a guided pre-wipe readiness workflow, archive restoration, a root backend, and a CLI are not implemented yet. The current archive is a ZIP/DEFLATE container and is not encrypted; SHA-256 checksums help detect payload corruption but do not protect private contents. Treat archives as sensitive and keep a copy somewhere other than the device you may wipe.
